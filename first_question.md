Я собираюсь разработать метод многомодального многозадачного многозначного (multimodal multitask multilable) распознавания паркинсона (2 класса) и депрессии (2 класса). В качестве модальностей планирую использовать аудио, видео, текст и описание или фичи LLM (например, Qwen3-Omni-30B-A3B-Instruct). Разрабатываемые метод должен отличаться своей новизной, потому что планируется опубликовать в A* конференции или в журнале Q1. Данные паркинсона и депрессии не пересекаются, то есть это фактически это два разных корпуса - по депрессии и паркинсону. Они не аннотированы на две задачи одновременно, как предполагают стандартный многозадачные методы. 

У меня уже есть стартовый проект на основе библиотеки https://github.com/markitantov/chimera_ml по многозадачному акустическому распознаванию паркинсона и депрессии. Смотри текущий код. Нужно проанализировать данный репозиторий.

Мои персональные требования к проекту: 
1) Нужно писать код в рамках библеотеки chimera_ml, нужно придерживаться стиля текущего audio (src/audio)
2) Исходный код многомодальных и одномодальных методов нужно отделять - в каждой папке своя модальность, например src/audio;src/video;src/text;src/fusion. Тоже самое касается всех экспериментов и конфигурационных файлов, то есть experiment_name должен быть общим для audio/video/text, а внутри этой папки уже частные эксперименты. Исключения составляют эксперименты в виде каких-то более глобальных надстроек к каждой модальности, например принципиально другой подход.
3) Все дополнительные скрипты писать в папку scripts/modality, а не в папку src 
4) Все регистрировать через registry.
5) Нужно обязательно использовать следующие внутренние методы chimera_ml и проекта с аудио: checkpoint_callback, snapshot_callback, early_stopping_callback, console_file_logger, mlflow_logger, wsm_summary_callback Другие callback можно тоже использовать, например какой-нибудь новый callback для интегрального вычисления показателей точности (см. wsm_segment_callback).
6) Какие-то общие, универсальные callback/loss и тд. складывать в папку common.
7) Выбор модели выполняется на DEV (Mean_Score = (Score_D + Score_P) / 2; Score_D = (UAR_D + MF1_D) / 2; Score_P = (UAR_P + MF1_P) / 2), однако также выводится точность TEST_NONE / TEST_SOFT / TEST_HARD просто для информации и для сравнения с другими методами, рассмотренными в статьях, включая DEPART (docs/BDCC-10-00089, docs/Ryumin_EMNLP).
8) Не нужно уделять много времеми одномодальным методам, за исключением видео и текста (максимум 2 эксперимента для выявления хорошие одномодальной модели!). В качестве видео надо реализовать DEPART-like модель. Текущий метод src/audio нужно использовать в качестве метода основы для аудио, модифицировать его нельзя. 
9) Основное внимание уделить многомодальному многозадачному многозначному (multimodal multitask multilable) методу.
10) Тесты можно не писать.
